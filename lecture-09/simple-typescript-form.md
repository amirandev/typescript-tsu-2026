# Pure TypeScript Forms Project — Guide for Students

## What is this project?

This is a **pure TypeScript** web project that demonstrates how to build forms with **client-side validation** — **without using any JavaScript framework** (no React, no Vue, no Angular, no jQuery).

It shows that you can write clean, type-safe code using TypeScript and have it run directly in the browser, with **zero runtime dependencies**. The only tool we install is the TypeScript compiler itself.

The project contains two forms:

| Page | Form | Validation Style |
|---|---|---|
| `contact.html` | Name, Email, Message | On submit |
| `register.html` | Username, Email, Password, Confirm Password, Role, Terms | Live (as you type) + async username check |

```
├── pure-ts-vs-react.md     # Comparison with React version
├── src/                    # 📁 TypeScript source code (we write code here)
│   ├── validation.ts       #   Shared validation functions
│   ├── contact.ts          #   Contact form logic
│   └── register.ts         #   Registration form logic
└── dist/                   # 📁 Compiled JavaScript (auto-generated by tsc)
    ├── validation.js       #   Compiled output
    ├── contact.js          #   Compiled output
    ├── register.js         #   Compiled output
    └── *.js.map            #   Source maps (for debugging)
```

### Key idea: `src/` vs `dist/`

- You write code in **TypeScript** (`.ts` files) inside `src/`.
- The TypeScript compiler (`tsc`) reads `src/` and outputs **plain JavaScript** (`.js` files) into `dist/`.
- The HTML pages load the `.js` files from `dist/`, **not** the `.ts` files.
- Browsers don't understand TypeScript — they only run JavaScript. The compiler translates your types and modern syntax into regular JS.

## How to Create This Project (Step by Step)

If you want to build this from scratch yourself, follow these steps:

### Step 1 — Initialize the project

```bash
mkdir pute-typescript-form
cd pute-typescript-form
npm init -y
```

This creates `package.json` with default values.

### Step 2 — Install TypeScript

```bash
npm install --save-dev typescript
```

We install TypeScript as a **dev dependency** because it's only needed during development (to compile). The browser never sees TypeScript.

### Step 3 — Configure TypeScript

Create `tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ES2020",
    "moduleResolution": "bundler",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "outDir": "dist",
    "rootDir": "src",
    "sourceMap": true
  },
  "include": ["src"]
}
```

Key settings explained:

| Setting | What it does |
|---|---|
| `"target": "ES2020"` | Output JavaScript that works in modern browsers |
| `"module": "ES2020"` | Keep `import`/`export` syntax (no bundler needed) |
| `"strict": true` | Enable all strict type-checking rules |
| `"outDir": "dist"` | Put compiled JS into the `dist/` folder |
| `"rootDir": "src"` | Look for `.ts` files in the `src/` folder |
| `"sourceMap": true` | Generate `.map` files for debugging |

### Step 4 — Add build scripts

In `package.json`, add:

```json
"scripts": {
  "build": "tsc",
  "watch": "tsc --watch"
}
```

- `npm run build` — compiles all `.ts` files once.
- `npm run watch` — watches for file changes and recompiles automatically.

### Step 5 — Create the HTML pages

Create `index.html`, `about.html`, `contact.html`, and `register.html`. Each HTML page that uses TypeScript must include a `<script>` tag pointing to its compiled JS file:

```html
<script type="module" src="dist/contact.js"></script>
```

Note: `type="module"` tells the browser to treat this as an ES Module, which lets us use `import` and `export` in the browser.

### Step 6 — Write the TypeScript source files

Create files inside `src/`:

- `src/validation.ts` — shared validation functions
- `src/contact.ts` — contact form handler
- `src/register.ts` — registration form handler

### Step 7 — Compile and run

```bash
npm run build
```

Then open any `.html` file in your browser.

## How the Code Works

### `src/validation.ts` — The shared brain

This file exports reusable validation functions:

```typescript
validate(field, value, allValues?)  // Returns "" if valid, or an error message
isFormValid(errors)                 // Checks if all errors are empty
clearErrors(container, fields)      // Removes all error messages and red borders
showError(container, field, msg)    // Shows an error message + red border
```

Each field has its own validation rules:
- **Name**: minimum 2 characters
- **Email**: must contain `@` and `.`
- **Message**: minimum 10 characters
- **Username**: minimum 3 characters, only letters/numbers/underscores
- **Password**: minimum 6 characters
- **Confirm Password**: must match the password field
- **Accept Terms**: must be checked

### `src/contact.ts` — Submit-time validation

- Waits for the form to be submitted.
- Reads all values using `FormData`.
- Calls `validate()` on every field.
- If there are errors, displays them using `showError()`.
- If valid, shows an alert and simulates a redirect.

### `src/register.ts` — Live validation

- On page load, applies default values and shows them.
- On every keystroke (`input` event), re-validates **all** fields.
- Updates error messages and red borders immediately (no need to wait for submit).
- **Async username check**: When the username is 3+ characters, waits 600ms (debounce) then simulates a server check (500ms delay) against a blacklist: `"admin"`, `"root"`, `"test"`.
- On submit, checks once more and submits only if everything is valid.

### How errors are displayed

Each form field has a `<p class="error" data-error="fieldname">` element right next to it. This element is always in the HTML — we just set its `textContent` to show/hide error messages. The `.field-error` CSS class adds a red border to invalid inputs.

This pattern is called **"uncontrolled inputs"** — the DOM is the source of truth, and we read values from it when we need them (instead of keeping a separate state variable like in React).

## How to Run the Project

### 1. Install dependencies

```bash
npm install
```

### 2. Compile TypeScript

```bash
npm run build
```

### 3. Open in browser

Simply open any `.html` file by double-clicking it or dragging it into your browser. **No server is needed** because there is no bundler — the browser loads the ES modules directly from `dist/`.

### For development (auto-recompilation)

```bash
npm run watch
```

Leave this running in the background. Every time you save a `.ts` file, it will recompile automatically. Then just refresh the browser page.

### What makes this "pure TypeScript"?

| Aspect | This project | React/Angular/Vue |
|---|---|---|
| Runtime dependencies | **Zero** | Many (react, react-dom, etc.) |
| Build tool | `tsc` only | Webpack, Vite, CRA, etc. |
| State management | DOM is the source of truth | Virtual DOM, component state |
| Rendering | Static HTML + imperative DOM updates | Declarative JSX/templates |
| Bundle size | Tiny (a few KB) | Hundreds of KB minimum |

### What did we learn?

1. **TypeScript is just a compiler** — it turns your typed code into plain JS.
2. **You don't need a framework** to build interactive web pages. The DOM API (`querySelector`, `addEventListener`, `textContent`, `classList`) is powerful enough.
3. **ES Modules** let you split code into multiple files and share functions via `import`/`export` — no bundler required.
4. **Form validation** has two common patterns: **submit-time** (check everything when the user clicks submit) and **live** (check as the user types). This project demonstrates both.
5. **Debouncing** prevents excessive work when checking async data (like username availability) during fast typing.
