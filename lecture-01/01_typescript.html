პირველი ნაბიჯები თანამედროვე ტიპიზირებული კოდის სამყაროში

TypeScript-ის არსი • გარემოს მომზადება • tsconfig.json • პირველი პროექტი • Watch რეჟიმი

სასწავლო მიზნები

რა არის მთავარი ამოცანა?

ამ ლექციის განმავლობაში ჩვენ სრულად გავივლით TypeScript-ის სამუშაო გარემოს ინსტალაციის, გამართვისა და კონფიგურაციის სრულ ციკლს.

მზად ვიქნებით რეალური პროექტების ასაწყობად.

  • გავიგოთ რა არის TypeScript და რატომ გამოვიყენოთ
  • დავაყენოთ TypeScript გარემო (Node.js, npm, tsc)
  • გავეცნოთ tsconfig.json კონფიგურაციას
  • ავაწყოთ პირველი TypeScript პროექტი
  • ვისწავლოთ კომპილაცია და watch რეჟიმი

სლაიდი 1: რა არის TypeScript?

TypeScript არის JavaScript-ის სუპერსეტი — ენა, რომელიც აფართოებს JavaScript-ს სტატიკური ტიპების მხარდაჭერით.

JavaScript + ტიპები = TypeScript

რატომ არის საჭირო TypeScript?

წარმოიდგინეთ, წერთ JavaScript კოდს და ხშირად ხვდებით შეცდომებს, რომლებიც მხოლოდ გაშვებისას ვლინდება. TypeScript ამ პრობლემას წყვეტს — ის შეცდომებს პოულობს კოდის აწყობისას (compile-time), სანამ კოდი მომხმარებლამდე მივა.

მთავარი უპირატესობები:

  • 🛡 შეცდომების გამოვლენა — ტიპების შემოწმება ხდება კომპილაციის დროს
  • 💡 უკეთესი IDE მხარდაჭერა — ავტოშევსება, რეფაქტორინგი, IntelliSense
  • 📖 თვითდოკუმენტირება — კოდის კითხვისას ტიპები გვეუბნება რას ელოდება ფუნქცია
  • 🔒 უფრო უსაფრთხო კოდი — ნაკლები bug-ები, უფრო პროგნოზირებადი ქცევა

TypeScript ≠ ახალი ენა!
TypeScript კოდი კომპილირდება ჩვეულებრივ JavaScript-ში, რომელიც მუშაობს ნებისმიერ ბრაუზერსა და Node.js-ზე.

სლაიდი 2: სცადე TypeScript ბრაუზერშივე — Playground

TypeScript-ის გასინჯვა არაფრის დაყენებას არ საჭიროებს! არსებობს ონლაინ ინსტრუმენტები:

🎮 TypeScript Playground (ოფიციალური)

https://www.typescriptlang.org/play/
  • მაიკროსოფტის ოფიციალური ინსტრუმენტი
  • რეალურ დროში აჩვენებს კომპილირებულ JavaScript-ს
  • შეგიძლიათ სხვადასხვა tsconfig ოფციების ტესტირება და გაზიარება

🎮 PlayCode.io TypeScript

https://playcode.io/typescript

დავალება: გახსენით Playground და სცადეთ:

let message: string = "Hello TypeScript!";
console.log(message);

სლაიდი 3: Node.js და npm-ის ინსტალაცია

Node.js — JavaScript-ის runtime გარემო, რომელიც საშუალებას გვაძლევს გავუშვათ JavaScript სერვერის გარეშე.

npm (Node Package Manager) — პაკეტების მენეჯერი, რომელსაც ვიყენებთ TypeScript-ის დასაყენებლად.

ინსტალაციის ნაბიჯები:

  1. გადადით საიტზე: https://nodejs.org
  2. ჩამოტვირთეთ LTS ვერსია (რეკომენდებული)
  3. გაუშვით ინსტალატორი — ის ავტომატურად დააყენებს ორივეს

ვერიფიკაცია ტერმინალში:

node --version   # მაგ: v20.11.0
npm --version    # მაგ: 10.2.4

პლატფორმული ალტერნატივები:

Windows (winget):

winget install OpenJS.NodeJS.LTS

macOS (Homebrew):

brew install node

Linux (Ubuntu/Debian):

sudo apt update && sudo apt install nodejs npm

💡 შენიშვნა: ინსტალაციის შემდეგ გადატვირთეთ ტერმინალი.

სლაიდი 4: TypeScript-ის ინსტალაცია

წინაპირობა: Node.js და npm უნდა იყოს წარმატებით დაყენებული სისტემაში.

ნაბიჯი 1: ვერსიების შემოწმება

დარწმუნდით, რომ Node-ის გარემო აქტიურია:

node --version
npm --version

ნაბიჯი 2: პროექტის შექმნა

შექმენით ახალი საქაღალდე და გააკეთეთ npm ინიციალიზაცია:

mkdir my-ts-project
cd my-ts-project
npm init -y

ნაბიჯი 3: TypeScript-ის ინსტალაცია

ჩვენ ვაყენებთ TypeScript-ს როგორც დეველოპმენტ პაკეტს (devDependency):

npm install typescript --save-dev

ეს ბრძანება პროექტში დაამატებს TypeScript კომპილერს, რომლის გაშვებასაც შევძლებთ npx tsc-ის მეშვეობით.

სლაიდი 5: tsconfig.json - კონფიგურაცია

TypeScript-ის ქცევის მართვისთვის საჭიროა კონფიგურაციის ფაილის გენერირება:

# tsconfig.json-ის გენერაცია
npx tsc --init

ეს ბრძანება შექმნის ფაილს, სადაც შეგვიძლია მივუთითოთ კომპილატორის სხვადასხვა ოფციები, სამიზნე ვერსიები და საქაღალდეების სტრუქტურა.

სად იქმნება ფაილი? ის იქმნება პროექტის ძირეულ (root) დირექტორიაში, სადაც package.json მდებარეობს.

მთავარი ოფციები tsconfig.json-ში:

{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "rootDir": "./src",
    "outDir": "./dist",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  }
}

სლაიდი 6: პროექტის სტრუქტურა

სწორად ორგანიზებული პროექტის საქაღალდეების სტრუქტურა ასე გამოიყურება:

my-ts-project/
├── src/              # წყაროს კოდი (.ts ფაილები)
│   └── index.ts
├── dist/             # კომპილირებული კოდი (.js ფაილები)
│   └── index.js
├── node_modules/
├── package.json
└── tsconfig.json

src/ საქაღალდე

აქ ვწერთ ჩვენს ორიგინალ TypeScript (.ts) ფაილებს.

dist/ საქაღალდე

აქ ავტომატურად გენერირდება კომპილირებული JavaScript (.js) ფაილები მას შემდეგ, რაც გავუშვებთ კომპილატორს.

სლაიდი 7: პირველი TypeScript კოდი

src/index.ts

let message: string = "Hello TypeScript!";
console.log(message);

function greet(name: string): string {
  return `გამარჯობა, ${name}!`;
}

console.log(greet("ნინო"));

კომპილაცია და გაშვება

ტრიგერისთვის ტერმინალში გაუშვით შემდეგი ბრძანებები:

1. კომპილაცია:

npx tsc

2. გაშვება:

node dist/index.js

სლაიდი 8: HTML-თან ინტეგრაცია

თუ გსურთ კოდი ბრაუზერში გაუშვათ, შექმენით index.html ფაილი პროექტის ძირეულ საქაღალდეში:

<!DOCTYPE html>
<html lang="ka">
<head>
  <meta charset="UTF-8" />
  <title>TypeScript App</title>
</head>
<body>
  <div id="app"></div>
  <script type="module" src="dist/index.js"></script>
</body>
</html>

უმნიშვნელოვანესი დეტალი:

tsconfig.json-ში:

დააკონფიგურირეთ "module": "ESNext" რათა ბრაუზერში type="module"-მა გამართულად იმუშაოს.

ბრაუზერი პირდაპირ ვერ კითხულობს TypeScript ფაილებს, ამიტომ ჩვენ მას ყოველთვის ვაწვდით კომპილირებულ dist/index.js ფაილს.

სლაიდი 9: Watch რეჟიმი

ყოველ ჯერზე ფაილის ცვლილებისას npx tsc-ის ხელით წერა დამღლელია. ამისთვის არსებობს Watch რეჟიმი.

ავტომატური კომპილაცია ფაილების ცვლილებისას:

npx tsc -w

როგორ მუშაობს იგი?

  • Watch რეჟიმი გამუდმებით თვალყურს ადევნებს .ts ფაილებს.
  • ნებისმიერი ცვლილების შენახვისთანავე (Ctrl+S / Cmd+S), ის მომენტალურად ახდენს კომპილაციას ფონურ რეჟიმში.
  • ეკრანზე მაშინვე გამოჩნდება შეცდომები, თუკი ისინი არსებობს.

სლაიდი 10: npm Scripts

package.json-ში სკრიპტების დამატება გვეხმარება მარტივად გავუშვათ ხშირი ბრძანებები:

{
  "scripts": {
    "build": "npx tsc",
    "start": "node dist/index.js",
    "dev": "npx tsc -w",
    "build:start": "npx tsc && node dist/index.js"
  }
}

როგორ გამოვიყენოთ:

პროექტის ასაწყობად:

npm run build

პროექტის გასაშვებად:

npm run start

დეველოპმენტ (watch) რეჟიმისთვის:

npm run dev

სლაიდი 11: strict რეჟიმი

strict: true ჩართავს ყველა მკაცრი ტიპების შემოწმების ოფციას. ეს არის საუკეთესო პრაქტიკა უსაფრთხო კოდისთვის:

ოფცია აღწერა
strictNullChecks null/undefined-ის მკაცრი შემოწმება (არ გვაძლევს საშუალებას შემთხვევით წავიკითხოთ ცარიელი მნიშვნელობა).
noImplicitAny იმპლიციტური any-ს აკრძალვა (ტიპი აუცილებლად მისათითებელია, თუ კომპილერი ვერ ხვდება თავისით).
strictFunctionTypes ფუნქციების ტიპების მკაცრი შემოწმება.
strictBindCallApply bind/call/apply მეთოდების ტიპების მკაცრი შემოწმება.

💡 რეკომენდაცია: ყოველთვის გამოიყენეთ strict: true ახალი პროექტების დაწყებისას!

სლაიდი 12: exclude / include

კონფიგურაციის ფაილში შეგვიძლია მივუთითოთ, თუ რომელი ფაილები ჩაერთოს ან გამოირიცხოს კომპილაციის პროცესიდან:

{
  "exclude": [
    "node_modules", 
    "dist", 
    "**/*.test.ts"
  ],
  "include": [
    "src/**/*.ts"
  ]
}

📂 include

განსაზღვრავს რომელი ფაილები ჩავრთოთ კომპილაციაში. ჩვენს შემთხვევაში ყველა .ts ფაილი src/ საქაღალდეში.

🚫 exclude

განსაზღვრავს რომელი ფაილები ან საქაღალდეები იქნეს უგულებელყოფილი (მაგ: დაინსტალირებული ბიბლიოთეკები node_modules ან ტესტები).

შეჯამება

  • TypeScript არის JavaScript-ის სუპერსეტი ტიპებით, რომელიც ზრდის კოდის უსაფრთხოებას.
  • ინსტალაცია ხდება მარტივად: npm install typescript --save-dev.
  • კონფიგურაციისთვის ვიყენებთ npx tsc --init ბრძანებას, რომელიც ქმნის tsconfig.json-ს.
  • კოდს ვწერთ src/ საქაღალდეში, ხოლო კომპილირებული კოდი თავსდება dist/-ში.
  • კომპილაციისთვის ვიყენებთ npx tsc-ს, ხოლო ავტომატური რეჟიმისთვის npx tsc -w (Watch რეჟიმი).
  • npm scripts საგრძნობლად ამარტივებს და აჩქარებს ყოველდღიურ მუშაობას.
